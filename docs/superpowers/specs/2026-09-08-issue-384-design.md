# 선택적 aggregate 감사 adapter 설계

## 목표와 승인 범위

#384와 승인된 7개 PR 계획에 따라 Exposed aggregate를 수정하지 않고 JaVers에 감사한다.
기존 AggregateRepository의 타입 경계와 기존 ABI를 유지한다. 새 필수 의존성이나 배포
모듈은 추가하지 않는다. 기준은 develop ced96068이며 Exposed AggregateRoot의
snapshot/clear/drain 계약을 대조했다.

## 대안과 결정

- 선택: javers-ddd에 추출 함수 기반 adapter와 1회용 registration을 추가한다.
- 제외: 별도 Exposed integration artifact는 BOM·CI·배포 비용이 커진다.
- 제외: 기존 AggregateRepository의 bound를 제거하면 기존 하위 클래스 계약이 달라진다.

## API와 책임

AggregateAuditAdapter<A,E>는 eventsOf, clearEvents, eventMapper를 받는다. Mapper는
원래 event를 기존 DomainEvent로 변환한다. DomainEvent의 기본 eventType 속성은
기존 클래스 이름이며 mapper는 원래 event type을 보존하도록 재정의할 수 있다.
캡처는 원래 event 참조를 독립 list에 보존하고 원본 aggregate를 유지한다.

Registration은 audit(Javers, author), publish((E)->Unit), complete(AuditCompletion)을
분리한다. 감사는 원본 aggregate와 기존 toJaversProperties 변환을 재사용한다.
#381은 동일 변환의 다중 이벤트 metadata 보존을 담당하며 이 adapter PR은 그 구현을
복사하지 않는다. 두 PR은 develop 대상이고 합친 상태에서도 검증한다.

COMMITTED는 호출자가 실제 transaction 완료를 확인한 뒤 전달하는 명시적 결과다.
ROLLED_BACK/UNKNOWN에서는 buffer를 건드리지 않는다. COMMITTED, audit 성공, 전체 publish
성공, 현재 buffer의 원소 참조·순서 일치가 모두 성립해야 clear한다. 비어 있는 캡처는
나중에 추가된 event를 지우지 않는다. 메서드는 단일 호출자 소유이며 동시 호출은 지원하지 않는다.

## 실패와 재시도

- mapper 또는 audit 예외: publish와 clear를 수행하지 않는다.
- 부분 publish 실패: 전체 buffer를 유지한다. 새 registration으로 재시도하면 이미 전달한
  이벤트가 중복 전달될 수 있으므로 소비자가 멱등성을 소유한다.
- rollback/unknown: 완료 통지가 있어도 buffer를 유지하고 registration은 종료한다.
- 캡처 이후 append/replace/reorder: clear 전에 거부하여 새 이벤트를 보존한다.
- clear 실패: 예외를 노출하며 성공으로 표시하지 않는다. 실패한 registration은 재사용하지 않는다.
- 중복 audit/publish/complete: 성공한 단계를 재실행하지 않도록 상태 검증한다.

외부 transaction hook이나 outbox를 소유하지 않으며 exactly-once를 보장하지 않는다.
운영 단계 실패는 기존 KLogging으로 고정 단계 이름과 예외 클래스만 기록한다.
Throwable 자체, 메시지, author, ID, type, attributes, 이벤트 객체는 기록하지 않는다.
CancellationException은 그대로 전파한다.

## 완료 조건

1. Exposed aggregate가 두 marker를 구현할 필요 없는 실행 가능한 사용 예제.
2. 원본 aggregate type, ID, 발생 시각, attributes와 원래 event type 보존.
3. 성공·감사 실패·부분 발행 실패·rollback·unknown·buffer 변경·중복 호출·빈 캡처 검증.
4. 기존 ABI 항목 유지, additive 항목만 갱신, 비 Exposed 소비자의 필수 의존성 유지.
5. 한국어 KDoc, README 두 언어, 회귀 테스트, 교훈, 독립 리뷰와 CI.

## 검토 보완 계약

모든 callback은 호출자 스레드에서 동기 실행된다. adapter는 자동 재시도·dispatcher·transaction을
만들지 않는다. 호출자는 원격 I/O timeout과 실행 스레드, transaction 길이, 최대 이벤트 수와
최대 재시도 횟수를 정한다. 각 registration은 mapper/publisher를 이벤트당 최대 한 번 호출하며
실패한 registration은 재사용하지 않는다. 새로운 registration을 만드는 재시도 비용은 O(N × 시도 수)다.
버퍼는 작은 aggregate 단위 사용을 전제로 하며 한 캡처의 보관·변환 비용은 O(N)이다.
100개 이벤트에서 호출 횟수가 선형인지 검증한다. 라이브러리가 임의의 전역 제한이나 전송 checkpoint를
도입하지 않는다. 특히 checkpoint는 DB rollback 이후 재발행 의미를 바꿀 수 있다.

이벤트는 불변 값이어야 하고 aggregate 상태는 캡처부터 완료까지 단일 호출자가 고정한다.
callback은 이벤트/aggregate를 변경해서는 안 된다. 참조·순서 검사는 buffer 교체/추가를 탐지하며
임의 객체의 내부 변경을 탐지하는 보안 경계가 아니다. mutable 외부 모델은 호출자가 불변 snapshot으로
매핑하거나 별도 버전 검증을 제공한 뒤 사용해야 한다. generic adapter는 임의 객체를 deep-copy하지 않는다.
clearEvents는 원자적으로 전체 캡처를 제거하거나 변경 없이 실패해야 한다. 부분 삭제 후 예외를 던지는
callback은 지원 계약 밖이며 adapter가 복구를 보장하지 않는다. 실패 시 registration.events에 보존한
참조를 복구 증거로 조회할 수 있다. 실제 Exposed clearDomainEvents는 이 계약과 대조한다.
이 전제와 한계는 KDoc와 README 두 언어에 동일하게 명시한다.

## 호출 순서와 transaction 경계

정상 순서는 capture → source transaction 안의 audit → source transaction 성공 반환 확인 →
publish → complete(COMMITTED)다. publish는 원본 E를 전달하며 mapper 결과를 다시 계산하지 않는다.
mapper는 audit에서 한 번씩만 호출한다. source transaction 실패/결과 불명은 audit 이후 어느 시점에도
complete(ROLLED_BACK/UNKNOWN)으로 종료하고 publish하지 않는다. adapter는 transaction 완료 여부를
독자적으로 알 수 없으므로 호출자가 성공 반환을 확인하기 전에 publish하는 것은 지원 계약 밖이다.
JaVers 저장소가 source transaction에 참여하는지는 해당 backend의 계약에 따른다. 분산 원자성을
보장하지 않는다. publish 실패 후 DB는 이미 commit되었으며 buffer 재시도는 at-least-once다.
메서드는 callback 진입 전에 상태를 예약하고 재진입·중복 호출을 거부한다.

## 확정 public signature

- `AggregateAuditAdapter<A : Any, E : Any>(eventsOf: (A) -> List<E>, clearEvents: (A) -> Unit, eventMapper: (E) -> DomainEvent)`
- `fun capture(aggregate: A): AggregateAuditRegistration<A, E>`
- registration 생성자는 internal이며 `val events: List<E>`, `fun audit(javers: Javers, author: String): Commit`,
  `fun publish(publisher: (E) -> Unit): Unit`, `fun complete(completion: AuditCompletion): Unit`을 공개한다.
- enum은 COMMITTED, ROLLED_BACK, UNKNOWN이다. 순서/중복 위반은 IllegalStateException이다.
- audit 이전에도 ROLLED_BACK/UNKNOWN 종료는 허용한다. callback 실행 중 완료는 거부한다.
- publisher는 캡처 순서대로 원본 E를 한 번씩 받는다. mapper는 원래 ID/시각/attributes를 보존해야 한다.
- eventType 기본값은 기존 `this::class.qualifiedName ?: this::class.java.name`과 정확히 같다.
