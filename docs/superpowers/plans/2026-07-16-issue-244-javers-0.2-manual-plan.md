# Javers 0.2 Manual Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a repository-owned, bilingual, release-validated Javers 0.2 manual covering five released libraries, one BOM, one DDD/CQRS example, one benchmark evidence group, and five audited dark diagrams.

**Architecture:** `docs/manual/` is the authoring source of truth. A manifest and Ruby contracts pin release `0.2.1` to commit `bffe19439ca891fa5301a76421bdef7ba75252a0`, classify the seven release projects, enforce English/Korean route parity, and expose deterministic SVG/PNG assets. The website later imports the merged source as a versioned `0.2` snapshot while preserving release and authoring provenance.

**Tech Stack:** Markdown/YAML/JSON, Ruby 3 standard library and Minitest, Gradle project inventory export, SVG, CairoSVG, Python diagram audits, Astro/Starlight website sync.

---

## File ownership map

- Publication contract owner: `docs/manual/manifest.yaml`, `docs/manual/generated/manifest.json`, `scripts/manual/*.rb`, root Gradle inventory task.
- Guide owner: `docs/manual/{en,ko}/{index.md,getting-started.md,architecture/**,persistence/**,guides/**,operations/**}`.
- Module owner: `docs/manual/{en,ko}/modules/*.md` for five libraries and the BOM.
- Learning owner: `docs/manual/{en,ko}/examples/javers-exposed-ddd.md` and `docs/manual/{en,ko}/benchmarks/exposed-ddd-envers.md`.
- Diagram/integration owner: `docs/manual/assets/**`, diagram validation, final manifest/index integration, publication metadata.

Workers must not edit another owner's paths. The integration owner resolves navigation, manifest, and shared-index changes after all content lanes finish.
