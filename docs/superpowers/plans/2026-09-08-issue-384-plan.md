# 선택적 aggregate 감사 adapter 구현 계획

목표: 승인된 추출 함수 방식을 명시적 완료 상태와 결합한다. Kotlin/JaVers의 기존
DomainEvent 변환과 Exposed의 buffer 소유권 계약을 재사용한다.

1. `javers-ddd/src/test/kotlin/io/bluetape4k/javers/ddd/AggregateAuditAdapterTest.kt`에
   성공·실패·rollback·unknown·변경된 buffer·중복 호출 테스트를 작성한다.
   `./gradlew :javers-ddd:test --tests '*AggregateAuditAdapterTest' --no-parallel --no-build-cache`로
   미구현 실패를 확인한다.
2. `javers-ddd/src/main/kotlin/io/bluetape4k/javers/ddd/AggregateAuditAdapter.kt`에
   adapter, registration, 완료 enum을 추가한다. DomainEvent.kt에는 기본 eventType만
   추가하고 기존 내부 eventTypeName을 위임한다. 기존 collection encoder는 그대로 사용한다.
3. 단계 상태는 시작 전 변경하여 실패한 registration을 재사용하지 못하게 한다.
   캡처 snapshot과 현재 buffer를 참조 동일성으로 비교하고 모든 성공 조건 이후에만 clear한다.
   coroutine API와 새로운 리소스 생성은 없으며 예외는 원형을 유지한다.
4. 기존 sibling Exposed aggregate의 사용 예제를 README.md/README.ko.md에 추가한다.
   테스트에서는 기존 Exposed dependency가 사용 가능한 소비 예제에서 실제 aggregate를 검증하고,
   javers-ddd production에는 Exposed import나 필수 dependency를 추가하지 않는다.
5. `:javers-ddd:cleanTest :javers-ddd:test --no-parallel --no-build-cache`, `checkKotlinAbi`, `git diff --check`를 실행한다.
   ABI는 기존 항목을 보존하고 새 항목만 dump한다. #381과 합친 통합 worktree에서 재검증한다.
6. 독립 spec/plan 및 diff 리뷰에서 P0/P1을 해소하고 lessons를 기록한다.
   실패 시 변경한 단계를 수리하고 해당 테스트와 영향을 받는 리뷰를 재실행한다.
   schema/data migration은 없으며 rollback은 이 additive API 사용과 커밋을 되돌리는 것이다.
7. feat/issue-384-aggregate-audit-adapter → develop PR을 생성한다.
   모든 PR 준비 후 exact HEAD·CI·리뷰를 모아 별도 병합 승인을 받는다.

문서 검토: 한국어 사용자 계획, 실제 symbol과 issue384 조건 대조, source/ABI/의존성/실패 경계
명시 완료. SPW-01~05를 적용하며 코드 완료·CI 성공은 아직 주장하지 않는다.

## 검토 보완 검증

- 빈 캡처 뒤 추가, callback의 buffer 변경, 원자적 clear 실패와 계약 밖 부분 clear 실패를 테스트한다.
  후자는 복구 보장이 없고 registration.events 참조가 남음을 명시적으로 검증한다.
- 원래 aggregate ID/type, 이벤트 type/시각/attributes 보존, 100개 mapper/publisher 호출 횟수,
  중복 audit/publish/complete에서 부수효과 미실행을 검증한다.
- README/KDoc에 동기 실행, 불변 이벤트·고정 aggregate, 원자적 clear, caller-owned timeout과
  최대 이벤트 수/재시도 횟수, 부분 실패의 중복 전달을 명시한다.
- 실패 로그는 단계/예외 클래스만 허용하고 Throwable 메시지/객체 전달 여부를 소스 리뷰한다.
- production source의 Exposed import 부재와 `:javers-ddd:dependencies --configuration runtimeClasspath`
  결과를 검증한다. 통합 worktree의 #381 commit SHA를 고정하고 indexed metadata 보존을 검사한다.

- 호출 순서 표를 테스트로 고정한다: audit 전 publish/COMMITTED 거부, callback 재진입 거부,
  audit 후 ROLLED_BACK/UNKNOWN은 clear/publish 없이 종료, 정상 publish 뒤 COMMITTED만 clear.
- mapper 예외, 실제 audit 예외, 부분 publish 후 새 registration의 중복 전달을 각각 검증한다.
- append/reorder/동등한 다른 참조 교체를 구분하고 rollback/unknown에서 원래 참조·순서를 검사한다.
- #381이 기존 public API를 바꾸지 않으므로 adapter 단독 구현을 진행할 수 있다. 다중 metadata 완료
  판정은 #381 commit을 고정한 통합 검증 이후에만 한다.

- audit 이전 ROLLED_BACK/UNKNOWN과 callback 예외 객체 동일성(CancellationException 포함)을 검증한다.
- 익명 DomainEvent의 기본 eventType fallback, publisher 원본 참조 순서, mapper의 ID/시각/attributes를
  테스트한다. ABI dump에서 기존 항목 유지와 getEventType/adapter/registration/enum 추가만 확인한다.
