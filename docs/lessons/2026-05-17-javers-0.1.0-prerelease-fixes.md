# 2026-05-17 — bluetape4k-javers 0.1.0 사전릴리스 버그 수정

## 근본 원인 분석

### 1. 무음 감사 로그 손상 (P0)

**문제**: `KafkaCdoSnapshotRepository.saveSnapshot` 에서 `catch(Throwable)` 이 모든 예외를 삼켰음.

```kotlin
// 수정 전 (위험)
override suspend fun saveSnapshot(snapshot: CdoSnapshot) {
    try {
        kafkaProducer.sendDefault(...)
    } catch (Throwable) {  // ← 예외 무시
        log.error(...)     // ← 로그만
    }
}
```

`AbstractCdoSnapshotRepository.persist()` 에서는 `saveSnapshot` 반환만 기다렸기 때문에, 예외가 발생해도 `head` 포인터가 진행됨. 결과: **감사 로그 누락, 오류 신호 없음**.

**결정**: Kafka 예외는 재발생 — 감사 무결성 > 가용성. Log-and-swallow 금지.

### 2. 숨겨진 NPE (P0)

**문제**: `AbstractCdoSnapshotRepository.encode()` 에서:

```kotlin
val jsonObject = jsonConverter?.toJsonElement() as JsonObject
//                           ↓ null이면 null 반환
//                                                ↑ null에 as JsonObject → NullPointerException
```

`jsonConverter` 가 `null` 이면 safe-call 은 `null` 을 반환하고, `as JsonObject` 캐스트가 발생 → 컨텍스트 없는 NPE.

**결정**: `requireNotNull()` 으로 앞에서 방어:

```kotlin
val converter = requireNotNull(jsonConverter) { "jsonConverter is required" }
val jsonObject = converter.toJsonElement() as JsonObject
```

### 3. Reflection 결과에 `!!` 연산자 사용 (P0)

**문제**: `ShadowProvider.getTypeMapper()`:

```kotlin
val field = declaredFields.find { it.name == "typeMapper" }!!
//                                                         ↑↑ NPE-prone
```

Javers 가 필드명을 언제든 변경하면 NPE 발생, 원인 불명.

**결정**: `requireNotNull()` 로 명확한 오류 메시지:

```kotlin
val field = requireNotNull(
    declaredFields.find { it.name == "typeMapper" }
) { "typeMapper field not found in ShadowProvider" }
```

### 4. MULTI/EXEC 스레드 안전성 (동시성 버그)

**문제**: Lettuce 의 동기 명령 객체는 연결당 1개이며, **스레드 안전하지 않음**.

```kotlin
// 스레드 A
redis.multi()       // ← MULTI 큐 시작
redis.set(...)      // ← 명령어 큐

// 스레드 B (A와 동시)
redis.set(...)      // ← A의 트랜잭션에 끼어듦 (인터리빙)

// 스레드 A
redis.exec()        // ← 혼합된 결과
```

**결정**: `transactionLock` 으로 MULTI/EXEC 직렬화:

```kotlin
private val transactionLock = ReentrantLock()

suspend fun <T> transaction(block: suspend () -> T): T = transactionLock.withLock {
    redis.multi()
    try {
        val result = block()
        redis.exec()
        result
    } finally {
        redis.discard()  // 안전 보장
    }
}
```

### 5. loadSnapshots 미락 (동시성 버그)

**문제**: Caffeine/Cache2K 저장소는 `saveSnapshot` 만 잠갔음:

```kotlin
// save는 잠금
lock.withLock {
    cache.put(key, snapshot)
}

// load는 잠금 없음 ← ConcurrentModificationException
fun loadSnapshots(...): List<CdoSnapshot> {
    return cache.asMap().values.toList()  // 동시 쓰기 중 읽음
}
```

**결정**: 읽기/쓰기 경로 모두 잠금:

```kotlin
suspend fun loadSnapshots(...): List<CdoSnapshot> = lock.withLock {
    return cache.asMap().values.toList()
}
```

### 6. `head` 포인터 `@Volatile` 미설정 (가시성 버그)

**문제**: `head: CommitId?` 는 `persist()` 내 lock 하에서만 쓰여지지만, `getHeadId()` 에서는 lock 없이 읽혔음:

```kotlin
// 스레드 A (락 소유)
lock.withLock {
    head = newCommitId  // ← 메모리 쓰기
}

// 스레드 B (락 없이 읽음)
fun getHeadId() = head  // ← JIT 최적화로 캐시된 값 읽을 수 있음
```

**결정**: `@Volatile` + 잠금 이중 보호:

```kotlin
@Volatile
var head: CommitId? = null

// persist()는 이미 lock.withLock을 사용 → 원자성 보장
// getHeadId()는 @Volatile으로 가시성 보장
fun getHeadId() = head
```

### 7. Kafka 블로킹 (타임아웃 없음)

**문제**: `.get()` 무한정 대기:

```kotlin
kafkaProducer.sendDefault(topic, key, value).get()  // ← 타임아웃 없음
// Kafka 브로커 응답 없으면 스레드 영구 블로킹
```

**결정**: 명시적 타임아웃 + 예외 재발생:

```kotlin
val future = kafkaProducer.sendDefault(topic, key, value)
try {
    future.get(10, TimeUnit.SECONDS)
} catch (e: TimeoutException) {
    throw IllegalStateException("Kafka broker timeout", e)
}
```

## 향후 지침

### saveSnapshot 구현 규칙

**모든 `saveSnapshot` 구현은 예외를 재발생시켜야 함** — 절대 무시하지 말 것.

`AbstractCdoSnapshotRepository.persist()` 는 예외 재발생에 의존하여 감사 로그 일관성을 보장함:

```kotlin
// ✅ 올바름 (예외 재발생)
suspend fun saveSnapshot(snapshot: CdoSnapshot) {
    try {
        backend.save(snapshot)
    } catch (e: Exception) {
        throw IllegalStateException("Failed to save snapshot", e)
    }
}

// ❌ 위험 (예외 무시)
suspend fun saveSnapshot(snapshot: CdoSnapshot) {
    try {
        backend.save(snapshot)
    } catch (Throwable) {
        log.error("...")  // ← 감사 로그 누락 위험
    }
}
```

### 신규 인메모리 저장소

**읽기와 쓰기 경로 모두 잠금하기**:

```kotlin
// ❌ 불완전
private val lock = ReentrantLock()
suspend fun saveSnapshot(...) = lock.withLock { ... }  // 쓰기만
suspend fun loadSnapshots(...) = cache.asMap().values  // 읽기 미잠금

// ✅ 올바름
private val lock = ReentrantLock()
suspend fun saveSnapshot(...) = lock.withLock { ... }
suspend fun loadSnapshots(...) = lock.withLock { cache.asMap().values }
```

### Nullable 체인에 `as T` 사용 금지

```kotlin
// ❌ NPE 컨텍스트 없음
val result = nullable?.method() as Type

// ✅ 명확한 오류
val result = requireNotNull(nullable).method() as Type
// 또는
val result = nullable?.let { it.method() as Type } 
    ?: throw IllegalStateException("nullable is null")
```

### catch(Throwable) 금지

**프로덕션 코드에서는 거의 항상 잘못됨**.

```kotlin
// ❌ 위험
try {
    operation()
} catch (Throwable) {
    log.error(...)
}

// ✅ 구체적 예외
try {
    operation()
} catch (e: IOException) {
    handleIOError(e)
} catch (e: CancellationException) {
    throw e  // 반드시 재발생
}
```

### Kafka 타임아웃

**모든 원격 호출에 타임아웃 설정**:

```kotlin
// ❌ 무한 대기 가능
kafkaProducer.sendDefault(...).get()

// ✅ 명시적 타임아웃
kafkaProducer.sendDefault(...).get(10, TimeUnit.SECONDS)
```

### 메모리 가시성 및 원자성

**멀티스레드 접근 필드는 `@Volatile` + 잠금 이중 보호**:

- `@Volatile`: 캐시된 값 읽음 방지 (읽기 가시성)
- `lock.withLock {}`: 쓰기 원자성 (상태 변경 안전)

```kotlin
@Volatile
var state: State? = null

suspend fun update(newState: State) = lock.withLock {
    state = newState  // @Volatile이 다른 스레드에 즉시 보임
}

fun getState() = state  // 항상 최신값 읽음
```
