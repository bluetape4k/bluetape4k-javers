# Open 0.2.1 Snapshot Line

## Context

After publishing `0.2.0`, `develop` still pointed at the released stable
version. The next work items need a new development line for snapshot
validation and future patch work.

## Decision

Set `baseVersion=0.2.1` and keep `snapshotVersion=` empty in git. The
`publish-snapshot.yml` workflow injects `-PsnapshotVersion=-SNAPSHOT` at publish
time, so checked-in project metadata remains a clean semantic base version.

## Outcome

The repository can publish `0.2.1-SNAPSHOT` from `develop` after CI/Nightly
validation without mutating the release tag.
